5단계 진행할건데. 유저 메시지를 text-embedding-3-small로 임베딩하고, pgvector로 해당 캐릭터(character_id 필터링)의 Memory를 유사도 검색해줘. Top-K는 5개, 코사인 유사도 threshold는 0.7 정도로 시작하고, fact/event 타입 구분 없이 함께 검색해서 섞이게 해줘. 검색된 기억은 build_system_prompt()에 주입해서 LLM 응답에 반영되게 해줘.

추가로 Memory Extraction 프롬프트에 요약 기준을 명시해줘 — '유저는 ~다' 형태의 3인칭 사실 서술로 20~40자 내외 한 문장으로 압축하고, 감정 뉘앙스는 text에 넣지 말고 emotion 필드에만 담도록. 그리고 Structured Output에 entities 필드(문자열 배열)를 하나 추가해서, 핵심 키워드 1~3개를 가볍게 같이 뽑아줘. 이건 나중에 '우리의 기억' 화면에서 태그로 보여줄 용도야.

0.7 was calibrated for a different embedding scale — text-embedding-3-small on short Korean sentences tops out around 0.40–0.53 even for genuinely relevant matches, and stays around 0.18–0.28 for unrelated ones. At 0.7 the search returns nothing, ever, which would make the RAG feature silently non-functional.

Important finding: the 떡볶이 fact scores lowest of all three memories for "나 배고파" (0.12) — even below the completely unrelated 야근 memories (0.17–0.20). This isn't a threshold-tuning problem; the relevant memory sits below the noise floor for this embedding model on this query. No threshold value can include it without also letting in noise.
